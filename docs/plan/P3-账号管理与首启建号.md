## 任务清单

### T3.1 首启建号页（`FirstRunSetup.qml`）

排在登录页**之前**，条件 = 账户库不存在（mock 阶段用 `MockData.accountsInitialized`
标志模拟）。流程：

1. 说明文案：这是超级用户，唯一内置账户，不可新建第二个、不可删除；
2. 输入工号 + 姓名 + 密码 + 确认密码；
3. 密码强度提示（长度 ≥8，含字母与数字——最终要求见开放问题 3）；
4. 创建后自动登录进产品门。

**不给"跳过"入口**。首启没有账户就没有审计归属，跳过等于让整批设备的产测记录
无人负责。

### T3.2 账号管理页（`ViewAccounts.qml`）

入口位置：导航栏底部「账号管理」，`visible: Session.canManageTech`（技术员看不见）。

页内两个区块：

| 区块 | 内容 | 可见条件 |
|---|---|---|
| 技术员列表 | 工号/姓名/状态；新建、重置密码、停用 | `canManageTech` |
| 工程师列表 | 同上 | `canManageEngineer`（仅超级用户） |

超级用户自身只显示一行「当前超级用户 工号 xxx · 修改密码」，**无删除按钮**。

**重置密码 = 生成临时密码并要求下次登录强制改**，不是直接设定新密码 ——
管理员不该知道别人的常用密码。

### T3.3 强制改密流程

重置后首次登录时插入改密页（`Session.user.mustChangePassword`）。改完才进产品门。

## 验收标准

- [ ] 技术员登录后，导航栏**看不到**账号管理入口（不是灰的，是没有）
- [ ] 工程师能建/重置技术员，**看不到**工程师区块
- [ ] 超级用户能建/重置工程师，自身无删除按钮
- [ ] 首启页无跳过入口；建号后直接进产品门
- [ ] 重置密码走临时密码 + 强制改密，不是明设新密
- [ ] 编译版零告警，实测走一遍三种角色

## 与 P5 的接缝

本批只做 UI 与 mock 数据的增删改（`MockData.users` 从 `readonly` 改可变）。
真实持久化在 P5。**mock 阶段就要把"重置=临时密码+强制改密"的流程走通**，
否则 P5 接后端时会为了省事退化成直接设新密。
