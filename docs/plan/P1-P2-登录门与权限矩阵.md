## 做了什么

启动流程从两段变三段：**操作者登录 → 产品选择门 → 工位主界面**。三者由 `Session`
的两个属性驱动，不用页面栈：

| Session 状态 | 显示 |
|---|---|
| `user === null` | ViewLogin |
| `user !== null && profile === null` | ProductGate |
| 两者都有 | 主界面（Loader 挂载） |

**为什么切换用户与切换产品行为不同**（这是刻意的，别"顺手统一"）：

- 切换产品 → `profile = null` → 主界面 Loader 卸载 → 设备连接、指令流水、各页状态
  **随对象树整棵销毁**。这是"换会话"的语义。
- 切换用户 → `user = null` → 回登录页，但 `profile` 保留 → 登录后直接回主界面，
  **设备连接与产品会话不动**。这是换班的语义（老产测惯例：换班不退软件）。

两个入口都在导航栏底部（分隔线下、暗色），与工位项区分。

## 权限矩阵实现

`Session` 暴露 `can*` 布尔量，UI 只读它、不自己判断角色字符串：

```qml
readonly property bool canSkipItem:        user !== null && user.role !== "tech"
readonly property bool canExport:          canSkipItem
readonly property bool canDebugPanel:      canSkipItem
readonly property bool canManageTech:      canSkipItem
readonly property bool canManageEngineer:  isSuper
readonly property bool canEditProfile:     isSuper
readonly property bool canEditCredentials: isSuper
```

这样加角色/调权限只改 `Session` 一处。**UI 惯例：无权限控件对技术员用
`visible: false` 直接隐藏，不用 `enabled: false` 置灰**（老软件 SW_HIDE 惯例，
工人看不见就不会问、不会反复点）。

已落的唯一受控控件：成品页「跳过当前项」→ `visible: Session.canSkipItem`。
**后续新增受控入口（调试面板/台账导出/账号页/设置页）在建的时候就挂矩阵，不回补** ——
回补必漏，这是这类权限系统最常见的破口。

## mock 与真实实现的边界

当前 `MockData.users` 是明文数组，`ViewLogin.tryLogin()` 直接比对 `pwd` 字段。
**这是演示层，P5 会整体替换**，替换时以下三点必须同时落地（缺一个都算没做完）：

1. 密码改 PBKDF2-HMAC-SHA256 加盐哈希（`QPasswordDigestor`，迭代 ≥10 万）；
2. 账户库 SQLite，与产测台账**分库分目录**（忘密兜底要能删账户库而不动台账）；
3. 登录页那行"演示账户…"提示删除。
